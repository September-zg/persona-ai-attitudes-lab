# C. AI 辅助开发记录

## 工具、目标与分工

使用 OpenAI Codex 进行需求拆解、HTML/CSS/JavaScript 与 Python 实现、测试、GitHub 和 Render 排查。负责人决定主题、提供老师要求、提出界面与解释问题、邀请真实朋友试用，并确认参与者独立性；AI 不能代替招募，也不在网站运行时决定分数。

问题拆成：测量与计分 → 同意/问卷/结果流程 → 保存和研究者汇总 → 测试与部署 → 真实试点 → 反馈分析与提交材料。现有原生前端和 Python 标准库服务器可以复现，故没有为了套用示例迁移到 Next.js/Supabase/Vercel。

这里摘录的是本项目真实请求与发生的核验，不使用参考对话中假设的“AI 写成 5-score”作为自己的经历。

## 本次确认的错误与修正

1. **离线说明与代码不一致。** 旧前端固定使用 `location.origin + '/api'`，直接打开文件时并不具备服务器。新版按 `file:` 和 HTTP(S) 区分，离线标识与保存位置对应；在线失败停留并提示重试。
2. **保存状态可能误导。** 旧答题发送失败后仍进入结果页，可能让参与者以为已经提交。新版仅在服务器确认后进入成功结果，使用提交编号保证同一次重试不新增记录。
3. **汇总回退可能混淆。** 旧版服务器读取出错时会回退到当前浏览器的数据。新版在线失败显示错误，不用本机记录冒充服务器汇总。
4. **后台缺少分数分布。** 旧版只有均值条和逐题分布，均值不等于维度分布。新版加入可选择维度的四区间分布图，并测试边界 1、2、3、4、5 的归属。
5. **权限只守住 API 不够。** 原 `SimpleHTTPRequestHandler` 可以将项目目录作为静态文件目录。新版只允许明确列出的前端资源，测试 GET/HEAD 无法取到 `data.json`、源码及私有目录；未配置密码时研究者接口也关闭。
6. **文档对统计与开发经历说得过满。** 旧文档将负 α 归因于反向计分，未充分区分历史日志与当前真实样本。新版保留真实尽责性 α=-0.80，解释原因未确定；不为了好看的统计修改答案。
7. **原生 Safari 编辑中文不可靠。** 前次网页输入造成部分中文丢失，且没有成功提交。此次以本地文件作为源文件，通过 GitHub 连接器同步，并核对提交内容，避免继续提交损坏的编辑草稿。
8. **拆分脚本后发生启动冲突。** 本次将题目抽为独立文件时，顶层变量与主脚本的常量重名；仅做语法检查没有发现，真实浏览器测试发现页面未启动。将定义封装在独立作用域后重新跑通浏览器流程，才准备发布。

## 如何验证，而不是直接接受输出

- Python：每个反向键、缺失/未知题、非法类型、边界值、独立维度与服务端重新计分。
- HTTP 临时服务器：静态路径授权、密码、提交去重、旧反馈兼容、仅追加恢复备份及重复导入幂等性。
- JavaScript：与 Python 固定键和计分结果逐一比较；独立已知数据验证 α=1、相关=-1、零方差和样本不足情况；合成记录排除与分布边界。
- 浏览器：同意门槛、漏答定位、返回修改、结果图、反馈、研究者登录、窄屏溢出与网络失败。
- 真实数据：先导出备份，再重算 11 份记录；公开材料仅发布去标识化汇总与反馈归纳。

实际命令、结果与发布状态集中在 [verification.md](verification.md)。旧时间线见 [development-log.md](development-log.md)，其中阶段性状态不代表最终状态。

## 反思

最大收获是把“代码写了”“本地可运行”“GitHub 已提交”“公网已更新”“用户理解了结果”分开验证。自动测试可以证明一部分计算与流程行为，不能证明题目有效、样本代表性或界面解释已经被参与者接受。后续优先做持久存储与原参与者复测，再扩展测量内容。
